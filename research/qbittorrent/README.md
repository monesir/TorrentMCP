# فحص محرك بحث qBittorrent وإعادة استخدام إضافاته

تاريخ الفحص: 2026-10-17. النطاق: خدمة بحث محلية مستقلة تتعامل مباشرة مع مواقع التورنت، مع فصل تنزيل المحتوى عنها.

## القرار المقترح

نبني مشغلا محليا لإضافات البحث المتوافقة مع qBittorrent، ونضع فوقه التحليل والفلترة والترتيب. يعاد استخدام تكامل المواقع القائم، وتبقى النتيجة الداخلية مستقلة عن صيغة qBittorrent. لا يعتمد تشغيل الخدمة على تثبيت qBittorrent أو Jackett أو تشغيل خدمة عامة.

هذا المجلد يحتوي فحصا قابلا للإعادة وإثبات تشغيل مستقل. لا يمثل خدمة البحث الإنتاجية أو إصدارا جاهزا للتوزيع.

## الأدلة وحدودها

| الدليل | ما يثبته | حدوده |
|---|---|---|
| `pe-resources.evidence.json` | فحص REA ساكن للملف التنفيذي المثبت، بصمة الملف وشجرة موارده | ليس تفكيكا للدوال ولا مراقبة لتشغيل التطبيق |
| `rea-provider-status.json` | عدم تهيئة محرك لفك الكود الأصلي في جلسة الفحص | لم نفك كود C++ ولم نثبت أدوات إضافية |
| `snapshot.manifest.json` | الملفات المحلية المختارة وأحجامها وبصماتها قبل التشغيل | الإضافات ملفات محلية قابلة للتحديث؛ وجودها لا يعني أنها جميعا مضمنة في الملف التنفيذي |
| `release-comparison.json` | تطابق ملفات المحرك الخمسة مع مصدر الإصدار 5.2.3 بعد توحيد نهايات الأسطر | لا يقارن جميع ملفات التطبيق أو كل الإضافات |
| `probe.results.json` | نتائج تشغيل إضافتين منفصلتين على مواقع حقيقية من نسخة مستقلة | صحة بيانات الموقع ومحتوى التورنت والسيدرز الفعليون غير متحقق منها |
| `resolution.results.json` | استخراج magnet من صفحة تفاصيل حقيقية بواسطة الإضافة | لم ينزل محتوى التورنت ولم يتحقق من سلامة محتواه |

## مسار التنفيذ الذي ثبت من الملفات والمصدر

1. يستدعي جانب C++ برنامج Python مستقلا لتشغيل `nova2.py`، ويمرر أسماء الإضافات والتصنيف وكلمات البحث.
2. يكتشف `nova2.py` ملفات Python داخل `engines`، ويستورد الصنف الذي يطابق اسم الملف.
3. تصف الإضافة اسمها وعنوان موقعها وتصنيفاتها، وتنفذ `search(query, category)`. كلمات البحث تصل مرمزة بواسطة `urllib.parse.quote`.
4. تستخدم الإضافة HTTP لاستدعاء JSON أو قراءة HTML. التصفح بين الصفحات وتفاصيل الموقع مسؤوليتها.
5. ترسل الإضافة النتائج عبر `novaprinter.prettyPrinter`. في الإصدار المحلي، المخرجات أسطر نصية تفصل حقولها بعلامة `|`.
6. يقرأ C++ النتائج تدريجيا من stdout. يستخدم المحرك تجمع عمليات لتشغيل المصادر، ويضع جانب C++ مهلة عامة قدرها ثلاث دقائق للبحث.
7. يستطيع `nova2dl.py` استدعاء `download_torrent` الخاصة بالإضافة للحصول على مرجع قابل للاستخدام عندما يحتاج الموقع إلى معالجة خاصة.

## الاختبار الفعلي

نسخ الفحص ملفات المحرك الخمسة وإضافتي `torrentscsv` و`limetorrents` فقط إلى `snapshot`. لم يقرأ إعدادات حسابات المستخدم أو إضافات أخرى. احتفظ بترويسات الملفات الأصلية.

التنفيذ كان بواسطة Python 3.14، باستعلام `ubuntu` وتصنيف `all`. برنامج qBittorrent التنفيذي لم يستدع في الاختبار.

| الاختبار | النتيجة في آخر تشغيل | الزمن التقريبي |
|---|---|---|
| اكتشاف الإضافات بواسطة `nova2.py --capabilities` | اكتشف الإضافتين؛ exit 0 | مسجل في JSON |
| بحث `torrentscsv` عبر JSON | 25 نتيجة، و25 رابطا مختلفا | 0.960 ثانية |
| بحث `limetorrents` عبر HTML | 160 نتيجة، و160 رابطا مختلفا | 4.508 ثانية |
| تحويل أول صفحة تفاصيل من LimeTorrents إلى magnet | نجح؛ exit 0 | 1.510 ثانية |

جميع أسطر البحث احتوت الحقول الثمانية المتوقعة وأمكن قراءة حقولها العددية. هذه نتائج ملاحظة في وقت الفحص، وليست ضمانا لثبات المواقع أو اكتمال النتائج. لم نختبر ترتيب الإصدارات أو البحث المتخصص بالأفلام والمسلسلات بعد.

كل إضافة شغلت في مفسر مستقل بمهلة عامة 20 ثانية ومهلة socket افتراضية 12 ثانية. هذا ضبط خاص بأداة الفحص، وليس سلوكا منسوبا إلى qBittorrent. فصل العمليات ليس عزلا أمنيا؛ الاختبار اقتصر على إضافتين قرئ كودهما قبل التنفيذ.

ظهر في أول تشغيل خطأ ترميز cp1252 أثناء طباعة مسار التقرير العربي، بعد حفظ النتائج. صححت طباعة الملخص، وأعيد التشغيل النهائي بنجاح مع `-X utf8`.

## ما نعيد استخدامه وما نؤلفه

| الجزء | الاتجاه |
|---|---|
| منطق الاتصال بكل موقع وتحليل صفحاته | تشغيل إضافات qBittorrent المختارة والمتوافقة |
| واجهات `helpers` و`novaprinter` التي تستوردها الإضافات | توفير طبقة توافق بإصدار مثبت، مع اختبار السلوك المطلوب |
| الإشراف على الإضافات | تأليف مشغّل بمهلة وإلغاء وأخطاء مستقلة لكل إضافة |
| البيانات الداخلية | نتائج منظمة تحتفظ بالمصدر والإضافة والحقول الأصلية والمجهول |
| تحليل الإصدارات والمطابقة والترتيب | طبقة مشتركة مستقلة عن إضافات المواقع |
| CLI وMCP | واجهتان لاحقتان لنفس عمليات البحث والتحليل |
| تنزيل المحتوى وإدارة مهامه | خدمة مستقلة تستقبل المرجع النهائي |

الواجهات الحالية للإضافات ليست عقدا مثاليا لطبقة التحليل؛ هي حد توافق مع نظام قائم. يمكن لاعتراض `prettyPrinter` في العامل تحويل القاموس مباشرة إلى JSON Lines داخلي، مع الحفاظ على السلوك الذي تتوقعه الإضافات. يجب اختبار الإضافات التي تكتب stdout مباشرة أو تعتمد على مساعدات أخرى قبل إعلان دعمها.

## نقاط يلزم معالجتها في خدمة البحث

1. **فصل البحث عن حل المرجع:** بعض النتائج magnet جاهز، وبعضها صفحة تفاصيل أو رابط ملف torrent. يحتفظ الناتج بنوع المرجع وبهوية الإضافة اللازمة لحله. جلب ملف torrent الصغير أو magnet جزء من تجهيز المرجع؛ تنزيل بيانات المحتوى مسؤولية خدمة التنزيل.
2. **نسخة بروتوكول التوافق:** الطابعة المحلية 1.53 تستبدل `|` في العنوان بمسافة. المصدر الأحدث الذي راجع سابقا يستخدم ترميز العنوان. نثبت نسخة المساعدات أو نستقبل القواميس مباشرة؛ لا نخمن طريقة فك الترميز من شكل النص.
3. **عزل فشل المصادر:** مستورد الإضافات في 5.2.3 يخفي استثناء الاستيراد ويعيد `None`. وعدم دعم تصنيف قد ينتهي دون نتائج أو خطأ صريح. نعلن حالات منفصلة للمصدر غير المدعوم، وتعذر تحميله، وفشله، وانتهاء مهلته، وإكماله بنتيجة فارغة.
4. **المهل وحدود العمل:** مساعد HTTP المحلي لا يمرر مهلة صريحة إلى `urlopen`. نحتاج سقفا لكل مصدر ولكل طلب، وحدودا للصفحات والنتائج، وإلغاء ينهي العملية وما أنشأته من عمليات إن وجد.
5. **النتائج الجزئية:** فشل مصدر لا يلغي نتائج غيره. تعاد حالة كل مصدر مع نتائج البحث.
6. **إزالة التكرار:** توحيد infohash عند توفره، ودمج ملاحظات المصادر دون جمع أعداد السيدرز. تبقى النتائج ذات الهوية غير المحسومة مستقلة حتى يتوفر دليل كاف.
7. **الثقة بالمعلومات:** أسماء الإصدارات وأعداد السيدرز والحجم معلومات مدعاة من المواقع. نحفظ المصدر ووقت الرصد ولا نحولها إلى ضمان لجودة المحتوى أو توفره.
8. **إدارة الإضافات:** أول إصدار يشغّل مجموعة مدققة ومثبتة الإصدارات والبصمات. الإضافة كود Python تنفيذي. لا نعتبر عملية فرعية حدود صلاحيات، ولا نحدث إضافات عشوائية ونشغلها تلقائيا.
9. **التوزيع المستقل:** نختبر حزمة تضم runtime Python والمساعدات والإضافات المختارة على جهاز لا يحتوي Python أو qBittorrent. هذا لم ينجز بعد.
10. **نسب المصدر والترخيص:** ترويسات ملفات المحرك المختارة تتضمن شروط إعادة الاستخدام، بينما تختلف ترويسات الإضافات. نحفظ نسب المصدر ونراجع ترخيص كل ملف قبل اعتماد قائمة التوزيع؛ لم ننسب ترخيص ملف إلى الجميع.

## ترتيب التنفيذ التالي

1. تثبيت عقد طلب البحث والنتيجة وحالة كل مصدر وحل المرجع.
2. بناء عامل توافق لإضافة واحدة، ثم تشغيل الإضافتين المثبتتين في هذا الفحص عبره.
3. إضافة المشرف الذي يدير المهل والإلغاء وتجميع النتائج الجزئية.
4. التحقق من السيناريوهات: موقع معطل، إضافة تفشل عند الاستيراد، تصنيف غير مدعوم، نتائج فارغة، ومرجع يحتاج صفحة تفاصيل.
5. إضافة تحليل أسماء الإصدارات والفلترة والترتيب، والتحقق على أعمال حقيقية تشمل حالات التباس.
6. توفير CLI قابل للاستخدام ثم واجهة MCP لنفس العمليات، واختبار التوزيع المستقل.

## إعادة الفحص

من جذر المستودع، باستخدام Python 3.10 أو أحدث متوافق مع ملفات snapshot:

```powershell
python -I -B -X utf8 research/qbittorrent/probe.py
python -I -B -X utf8 research/qbittorrent/probe.py --resolve-sample
python -I -B -X utf8 research/qbittorrent/probe.py --show-results
```

الأمر الأول يأخذ نسخة جديدة من الملفات المحددة في `%LOCALAPPDATA%\qBittorrent\nova3` ويستبدل أدلة الفحص السابقة، ثم ينفذ بحث HTTP في الإضافتين. يمكن تحديد مصدر آخر بواسطة `--source`. الأمر الثاني يستخدم أول نتيجة محفوظة من LimeTorrents ويستخرج مرجعها. الأمر الثالث يعرض الملخص المحفوظ دون اتصالات جديدة.

وجود ملفات qBittorrent المحلية مطلوب لإعادة أخذ العينة بهذه الأداة البحثية فقط، وليس قرارا باشتراط تثبيته لتشغيل المنتج النهائي.
