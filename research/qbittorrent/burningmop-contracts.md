# عقود إضافات BurningMop العامة للنقل إلى Rust

تاريخ الفحص: 2026-10-17. هذا تقرير قراءة ساكنة لصفوف BurningMop العامة في [كتالوج المجتمع المحفوظ](community-20261017/catalog.json) ولملفات Python الثابتة المشار إليها أدناه. عددها 15؛ النسخة المذكورة لكل ملف مأخوذة من ترويسة `# VERSION` في المصدر المحفوظ. لم أشغّل الإضافات ولم أختبر مواقعها الحية؛ المسارات والسلوك أدناه مستخرجان من المصدر، لذلك لا يثبتان أن الموقع متاح الآن.

## الملكية والترخيص

المستودع الأصلي يذكر أن محتواه، باستثناء سكربتات `nova` التابعة لـqBittorrent، تحت MIT، وملف [LICENSE](https://github.com/BurningMop/qBittorrent-Search-Plugins/blob/main/LICENSE) يتضمن إشعار BurningMop لعام 2023. عند شحن إعادة تنفيذ مشتقة من هذه الملفات، احتفظ بإشعار حقوق النشر ونص الإذن في مواد الطرف الثالث. [README للمستودع](https://github.com/BurningMop/qBittorrent-Search-Plugins#license) · [ملف LICENSE](https://github.com/BurningMop/qBittorrent-Search-Plugins/blob/main/LICENSE)

لا يظهر في هذه المصادر تسجيل دخول أو مفتاح API أو ملف إعداد اعتماد. بعض النتائج تتطلب طلب صفحة التفاصيل لاستخراج رابطها؛ هذا حل للرابط، وليس مصادقة.

## مجموعات تنفيذ مناسبة

1. **قالب البطاقات الإسباني المشترك**: divxtotal (016)، DonTorrent (021)، esmeraldatorrent (023)، NaranjaTorrent (037)، TomaDivx (061). المحددات وحل التفاصيل وشكل الاسم متطابقة عمليا: `#buscador` → `.card` → `.card-body` → `<p>` → `<span>` → `<a>`. يمكن بناء محلل واحد مع وصف لكل موقع، وتخصيص طريقة الطلب؛ DonTorrent وحده يستخدم POST، والأربعة الأخرى GET. أسماء hosts في أربعة من الملفات تنتهي بشرطة `/` ثم تضيف دالة البحث `/buscar`، فينتج مسار `//buscar`; سجّل ذلك في fixture وقرّر مع اختبار الموقع إن كان التطبيع آمنا. تبقى قواعد النطاق والصفحات منفصلة لكل موقع.
2. **استخراج صفحة التفاصيل إلى HTTP `.torrent`**: CalidadTorrent (012) وPediaTorrent (044) يصلح لهما resolver مشترك يعيد صفحة التفاصيل ثم يستخرج `<h1>` و`/torrents/*.torrent`، لكن parser صفحة البحث مختلف: `showDetail:true` عند Calidad، وقوائم فئات و`showDetail:false` عند Pedia.
3. **قوائم تستخرج magnet مباشرة**: Bit Search (009) وSolidTorrents (053) لا يحتاجان طلب تفاصيل للحصول على magnet؛ لكل منهما DOM مستقل على route بحث متقارب.
4. **قوائم تستخرج magnet بعد صفحة التفاصيل**: The RarBg (060)، Torrent Downloads Pro (067)، XXXClub (074) تشترك في فكرة resolver فقط؛ محددات الصفوف وترقيم الصفحات والفئات مختلفة، فلا تستخدم parser واحدا لها.
5. **منطق خاص يجب إبقاؤه منفصلا**: My Porn Club (036) بسبب بناء webseed الخارجي؛ Torrenflix (068) لأن صفحة التفاصيل تنتج عدة نتائج لكل title عبر server/language/quality؛ TrahT (070) لأنه يعيد رابط تنزيل `&ok=` من الصف مباشرة ولا يمر بصفحة magnet.

## تعليمات تنفيذية للمقارنة مع Python

- اعزل لكل إضافة وصفا ثابتا: host، تصنيفات qBittorrent، طريقة الطلب، بناء URL، وقواعد إنهاء الصفحات. عالج query encoding بمعيار URL في Rust، مع حفظ التحويل الدلالي الذي يطلبه المصدر (`+` أو `-`).
- اجعل pagination والطلبات التفصيلية محدودة ومتزامنة بحد معروف، وسجّل الصفحة أو النتيجة التي فشلت. عدة إضافات Python تنشئ threads مع علم توقف مشترك؛ لا تنقل سباقات الحالة أو الحلقات غير المحدودة كشرط توافق.
- طبّع نوع الرابط إلى `magnet` أو `torrent_url` أو `source_url` مع إبقاء النص الأصلي. لا تحوّل HTTP `.torrent` إلى magnet مفترض، ولا تحذف معاملات `&ok=` أو `ws`.
- احفظ `-1` للعداد المجهول و`0` للحجم الافتراضي كما تخرجه الإضافة، إلى أن يقرر عقد المنتج التحويل النهائي. لا تضع `pub_date` إلا حيث يستخرجه المصدر (Bit Search وMyPorn Club في هذه المجموعة).
- ملف Torrenflix المذكور أعلاه مرجع مصدر خارجي ولم يُنسخ إلى ملفات المجموعة؛ الملف المحلي الوحيد المضاف في هذا التغيير هو هذا التقرير.
