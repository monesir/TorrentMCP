# تقييم الملفات المفحوصة ومقارنتها

المقارنة للإيجنت على بيانات `inspect_torrent_file` الفعلية، وفق سياسة `inspected-media-v1`. لا تستخرج مواصفات من عنوان نتيجة البحث، ولا تختار عشوائيا عند تعدد الفيديو، ولا تستخدم بتريت الملف الإجمالي بديلا عن بتريت الفيديو. لا تقيس جودة الصورة الإدراكية أو تطابق العمل أو النسخة التحريرية؛ يختار الإيجنت مرشحي العمل المقصود.

## التقييم مع الفحص

أضف `analysis` إلى طلب inspect_torrent_file المعتاد:

```json
{
  "constraints": {
    "min_video_width": 1920,
    "audio_languages": ["en"],
    "subtitle_languages": ["ar"],
    "max_file_size_bytes": 8589934592
  },
  "preferences": {
    "video_codecs": ["hevc", "h264"],
    "rank_by": ["video_codecs", "smaller_file"]
  }
}
```

يعيد `result.assessment` مع الكتالوج والملف والمسارات. حالة الطلب completed تعني اكتمال القراءة؛ قد يكون التقييم excluded أو uncertain إذا لم تتحقق الشروط أو كانت المعلومة مجهولة.

## المقارنة دون إعادة فحص

```powershell
$first = Get-Content -LiteralPath inspection-a.json -Raw | ConvertFrom-Json
$second = Get-Content -LiteralPath inspection-b.json -Raw | ConvertFrom-Json
$analysis = Get-Content -LiteralPath examples/media-analysis.json -Raw | ConvertFrom-Json
@{schema_version=1; operation='compare_media'; analysis=$analysis;
  candidates=@(@{id='a'; inspection=$first}, @{id='b'; inspection=$second})} |
    ConvertTo-Json -Depth 60 | .\torrent-search.exe agent --output comparison.json
```

`inspection` هو غلاف استجابة الإيجنت كاملا، لا `result.media` وحده. يقبل 1..100 مرشح، ومعرفات فريدة لا تزيد عن 256 بايت. لا يسمح بتكرار التورنت والملف نفسيهما تحت معرفين. يمكن تحديد `video_stream_index` في المرشح إذا احتوى الفحص على أكثر من فيديو. تقارير 0.5 تقرأ كما هي؛ لا تشترط assessment محفوظا، وأي تقييم قديم لا يستخدم في القرار الجديد.

تعمل compare_media دون أصول البحث أو Python أو rqbit أو ffprobe، ولا تتصل بالشبكة ولا تعيد التنزيل. إخراج العمليتين JSON. يستخدم كل تقرير كامل كدليل محفوظ، مع تقييم جديد وأسباب ومصدر وفهارس المسارات لكل شرط.

## شروط القبول

| الحقل | المعنى |
| --- | --- |
| min_video_width / min_video_height | حد أدنى للأبعاد الفعلية بالبكسل، شامل الحد |
| video_codecs | يكفي أحد ترميزات ffprobe المقبولة، مثل hevc وh264 وav1 |
| audio_languages / subtitle_languages | يجب وجود كل لغة مطلوبة في مسار داخل الملف؛ تطبع eng/en وara/ar والرموز المعروفة |
| min_file_size_bytes / max_file_size_bytes | حد شامل لحجم الملف المختار كله، وليس حجم التورنت أو ملف remux افتراضي |
| min_video_bitrate_bps / max_video_bitrate_bps | حد شامل لبتريت مسار الفيديو فقط، من ffprobe_stream أو container_statistics_tag |

الحقول والقوائم اختيارية؛ القوائم الفارغة لا تضيف شرطا. الحدود الرقمية موجبة، والعرض والارتفاع ضمن 1..65535، ويجب ألا يتجاوز الحد الأدنى الحد الأعلى. أسماء الترميز بحروف صغيرة، واللغات 2 أو 3 أحرف صغيرة؛ ترفض und/mul/zxx والتكرار بعد التطبيع. الحقول المجهولة في الإعدادات ترفض.

الأبعاد أبعاد مشفرة فعلية، وليست تصنيف اسم الإصدار مثل 1080p. فيلم 1920×800 يجتاز min_video_width=1920، لكنه لا يجتاز min_video_height=1080. المثال يقيد العرض لملاءمة الأفلام ذات الصورة المقصوصة؛ لا يستنتج البرنامج دقة اسمية من عنوانه.

عند طلب لغة: وجود مسار موسوم بها يحقق الشرط؛ غيابها مع وجود مسار لغته مجهولة يجعل الشرط غير محسوم. لا يحكم بغيابها إلا عند اكتمال الفحص ومعرفة لغات المسارات المعنية. قائمة ترجمة فارغة في فحص مكتمل تعني غياب الترجمة داخل الملف؛ ملفات SRT الخارجية ليست جزءا من هذا الحكم. وسوم اللغات نفسها قد تكون خاطئة؛ لا يستمع الفاحص للصوت.

## الأهلية والفحص الجزئي

- eligible: كل الشروط المطلوبة متحققة، والفحص مكتمل وإغلاق الخدمة مؤكد.
- excluded: توجد مخالفة محددة، مع السبب والقيمة المرصودة.
- uncertain: لا توجد مخالفة حاسمة، لكن معلومة أو اختيار فيديو أو اكتمال الفحص غير محسوم.

المخالفة المقروءة الحاسمة تستبعد حتى مع فحص جزئي، لكن الفشل أو المهلة أو الفحص المفقود لا يجعل المرشح صالحا ولا يثبت غياب لغة. لا يستبدل البتريت المفقود بقيمة صفر أو بتريت الملف كله.

يتحقق المدخل من إصدار التقرير ومصدره وفهارس المسارات، ومن تطابق الملف والهاش والكتالوج وحجم تقرير الوسائط. هذه فحوص اتساق لتقرير محفوظ؛ ليست توقيعا يثبت أنه لم يعدل. يحتفظ بالمجهول والتقرير الأصلي ولا يخترع أدلة.

## الترتيب

ترتب فئات الأهلية أولا: eligible ثم uncertain ثم excluded. داخل كل فئة تطبق `preferences.rank_by` من الأول إلى الأخير؛ أول اختلاف يحسم الترتيب. الحقول المتاحة: video_codecs، audio_languages، subtitle_languages، smaller_file، larger_file، higher_video_bitrate، lower_video_bitrate، higher_video_pixels.

قوائم video_codecs/audio_languages/subtitle_languages مرتبة من المفضل إلى الأقل. إذا ترك rank_by فارغا تستخدم القوائم غير الفارغة بهذا الترتيب فقط. إذا حدد صراحة فيجب أن يتضمن كل قائمة تفضيل غير فارغة وألا يطلب قائمة فارغة. لا يسمح بمعايير مكررة أو اتجاهي الحجم أو اتجاهي البتريت معا. القيم المجهولة تأتي بعد القيم المعروفة في الاتجاهين. التعادل الكامل يحسم بمعرف المرشح، وليس بجودة مفترضة.

كل عامل ترتيب يظهر المعيار والاتجاه والقيمة والمفضل المطابق وسبب التطبيق. لا توجد أوزان مخفية أو درجة جودة، ولا يفضل البتريت العالي إلا إذا طلب صراحة. يحتفظ كل مرشح بالمسارات والبتريت والأحجام المتاحة في inspection حتى لو لم تدخل في شروط المقارنة.

استجابة compare_media تكون completed/0 إذا كانت الفحوص مكتملة، ولو استبعدت كلها أو بقيت لغة مجهولة؛ partial/3 عند وجود فحص مفقود أو متعثر أو جزئي. فساد العقد أو الهوية أو الإعدادات يعيد error/1. لا يعني المركز الأول أن هناك نسخة مقبولة؛ اقرأ الأهلية والملخص والأسباب.
