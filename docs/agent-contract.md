# عقد الإيجنت — الإصدار 1

`compare_media` يقبل `schema_version`, `analysis`, `candidates` ويعيد مقارنة على بيانات الفحص الفعلية، دون شبكة أو محرك تورنت. `inspect_torrent_file.analysis` اختياري لتقييم الملف فور فحصه. هذه إعدادات وسائط منفصلة عن تحليل أسماء الإصدارات؛ راجع [عقد المقارنة](media-comparison.md).

أضيفت عمليتا `torrent_files` و`inspect_torrent_file` لربط نتيجة البحث بقائمة الملفات ثم فحص ملف مختار عبر خدمة مستقلة. العقد الكامل والتسلسل في [مسار التورنت](torrent-workflow.md). لا تتغير طلبات search/analyze/inspect_media الحالية.

المستهلك الأساسي إيجنت. يشغل عملية محلية، يرسل طلب JSON واحدا، ويقرأ استجابة JSON واحدة من stdout وحالة خروج العملية. لا توجد أسئلة أو قوائم تفاعلية. هذه واجهة CLI؛ MCP لم يضف بعد. يمكن أن يغلف الواجهة نفسها لاحقا.

```powershell
.\torrent-search.exe agent --request .\examples\nirvana-agent-search.json
```

عند حذف `--request` يقرأ الطلب من stdin حتى EOF. الحد 16 MiB، والترميز UTF-8 مع قبول BOM. خيارات CLI غير الصحيحة تظل أخطاء clap وحالة خروج 2؛ الأخطاء داخل طلب الإيجنت واستدعاء المصادر تعاد بصيغة JSON. لا تعيد المحاولة لمجرد أن رمز الخروج غير صفري: اقرأ `status` و`error` و`sources` أولا.

## العمليات

`inspect_media`: الحقول المطلوبة `schema_version: 1`, `operation: "inspect_media"`, `media`. يفحص ملفا محليا أو نطاقات من خدمة تنزيل محلية؛ يحمل `result` تقرير وسائط بدل تقرير البحث. التفاصيل في [فحص الوسائط](media-inspection.md).

`search`: الحقول المطلوبة `schema_version: 1`, `operation: "search"`, `search`, `analysis`. يحتوي `search` على `query` و`category` و`sources`؛ المصفوفة الفارغة تختار المصادر المسجلة كلها. التصنيفات: all, anime, books, games, movies, music, pictures, software, tv. المعرفات الحالية: torrentscsv, limetorrents. المعرف المجهول خطأ، ولا يجري تجاهله.

`limits` اختياري. الافتراضات: `timeout_seconds: 20`, `parallel_sources: 4`, `results_per_source: 100`. الحدود على الترتيب 1..120، 1..16، 1..1000. المهلة والحد لكل مصدر. نتائج المصدر التي وصلت قبل فشله تبقى في التقرير.

`analyze`: الحقول المطلوبة `schema_version: 1`, `operation: "analyze"`, `report`, `analysis`. `report` تقرير بحث محفوظ من واجهة البحث الخام. هذه العملية تعمل دون شبكة أو Python أو ملفات المصادر، وتعيد التحليل حتى لو كان التقرير الأصلي جزئيا. تحتفظ الاستجابة بحالة ذلك التقرير.

مثال إعداد تحليل تقرير محفوظ:

```powershell
$request = @{
    schema_version = 1
    operation = 'analyze'
    report = Get-Content -Raw .\search-report.json | ConvertFrom-Json
    analysis = @{
        target = @{ title = 'Nirvana in Fire'; year = 2015; episodes = @{ start = 1; end = 54 } }
        constraints = @{ resolutions = @(1080); audio_languages = @('zh') }
    }
}
$request | ConvertTo-Json -Depth 30 | Set-Content -Encoding utf8 .\analysis-request.json
.\torrent-search.exe agent --request .\analysis-request.json
```

الحقول المجهولة في الطلب وإعدادات التحليل ترفض لكشف الأخطاء الإملائية. تقرير البحث المضمّن يقبل حقولا إضافية للتوافق مع الإصدارات اللاحقة؛ عناصره الحالية مطلوبة، و`raw_title` اختياري للتقارير القديمة.

## الهدف والشروط والتفضيلات

`analysis.target.title` مطلوب، ويزود الإيجنت `aliases` بالأسماء البديلة عند الحاجة. المطابقة تعتمد كلمات كاملة في بداية الاسم بعد تطبيع Unicode والفواصل، مع السماح بوسم مجموعة إصدار مثل `[Group]` في البداية. ليست بحثا ضبابيا أو تعريفا تلقائيا بالعمل. `year`, `season`, `part`, `episodes: {start, end}` حقول اختيارية؛ الحلقة الأولى والأخيرة مشمولتان.

القيود الإلزامية في `constraints`: `resolutions`, `codecs`, `audio_languages`, `coverage`, `min_size_bytes`, `max_size_bytes`, `min_seeders`. القوائم تعني قبول أي قيمة منها؛ القائمة الفارغة لا تضيف قيدا. الدقات ارتفاعات عددية: 480, 576, 720, 1080, 1440, 2160, 4320. الترميزات: h264, hevc, av1, mpeg2, xvid. اللغات: zh, en, ar, ja, ko, fr, de, es, ru, hi, th. التغطية: single_episode, episode_batch, season_pack, complete_claim.

`preferences` يقبل قوائم مرتبة للدقة والترميز ولغة الصوت والتغطية؛ أول عنصر أفضل. هذه ترفع الترتيب فقط ولا تستبعد النتائج. سياسة `release-analysis-v1`: أوزان الدقة 100، الترميز 60، الصوت 40، التغطية 40. نقاط القائمة = الوزن × (عدد العناصر − ترتيب العنصر من الصفر) ÷ عدد العناصر مع التقريب للأسفل. الخاصية المتعددة القيم لا تأخذ نقاطا. يرتب المحرك: أهلية المطابقة ثم مجموع النقاط ثم أعلى عدد سيدرز مبلّغ عنه ثم الاسم والرابط لكسر التعادل. عوامل النقاط ظاهرة في `ranking.factors`؛ ليست تقديرا لجودة الصورة الفعلية.

## تفسير النتيجة

الاستجابة تحمل `schema_version`, `status`, `result`, `error`. يحتوي `result` على التقرير الخام و`request`, `policy_version`, `summary`، ولكل نتيجة `analysis`, `eligibility`, `evaluations`, `ranking`. لا تحذف النتائج المستبعدة كي يستطيع الإيجنت فحص السبب. `summary` يعد eligible/uncertain/excluded.

| الحقل | المعنى |
| --- | --- |
| `eligible` | جميع الشروط المطلوبة تطابق المعلومات المستخرجة المتاحة |
| `uncertain` | لا يوجد تعارض حاسم، لكن شرطا مطلوبا مجهول أو متعدد الاحتمالات |
| `excluded` | يوجد شرط مطلوب يخالف المعلومات المتاحة |
| `unknown` | لم نجد معلومة قابلة للاستخراج |
| `claimed` | معلومة مكتوبة في العنوان؛ ليست فحصا للوسائط |
| `inferred` | استنتاج معلن من نمط تسمية، مثل II بعد اسم العمل |
| `ambiguous` | وجد المحرك أكثر من قيمة، مثل 4k&1080p |

كل خاصية تحتوي `claims`، وكل ادعاء يحتوي قيمته وأدلة `source_id`, `title_index`, `token`, `rule`. `title_index` يشير إلى عنصر `analysis.titles`. تبقى `raw` و`normalized` وسلسلة التصحيحات متاحة. يمكن إصلاح فساد ترميز Windows-1252/UTF-8 في نسخة التحليل عندما ينجح التحويل دون فقد ويقل عدد علامات الفساد؛ الاسم الأصلي والرابط لا يعدلان.

كلمة Complete تسجل `complete_claim`، ولا تثبت عدد الحلقات. اسم بلا أرقام لا يثبت أنه موسم كامل. English Subs ليست English Audio. II يستنتج جزءا ثانيا، ولا يحول تلقائيا إلى season 2. نطاقات الحلقات تحفظ الفجوات؛ S01E01E03 لا يغطي الحلقة 2. عمليتا search/analyze لا تفحصان محتوى الفيديو؛ لذلك أضيفت inspect_media مستقلة. لا يستعلم المحرك عن قاعدة بيانات للأعمال؛ على الإيجنت توفير الهدف بدقة وفحص الأدلة والمجهول قبل اختيار التنزيل.

الحجم والسيدرز كما أبلغ عنهما المصدر وفي وقت الرصد؛ أعلى عدد سيدرز يستخدم بدلا من جمعه عبر المصادر. لا يثبت هذا أن السيدرز قابلون للاتصال حاليا. رابط HTTP قد يكون صفحة تفاصيل؛ استخدم أمر `--json resolve --source ...` للحصول على magnet أو مرجع تنزيل HTTP حيث يدعمه المصدر. قد يتضمن مرجع HTTP الحقل الاختياري `post_form`، وهو خريطة حقول نموذج يجب إرسالها بطلب POST بترميز `application/x-www-form-urlencoded`؛ بدونه يستخدم المستهلك GET. هذا مرجع لخدمة التنزيل المنفصلة، وليس محتوى الملف.

## حالات الخروج

| status | الخروج | الإجراء المتوقع |
| --- | --- | --- |
| completed | 0 | فحص النتائج؛ الاكتمال قد يعني صفر نتائج |
| partial | 3 | الاستفادة من المتاح وفحص تقارير المصادر المتعثرة |
| failed | 1 | لم يكتمل أي مصدر؛ النتائج الجزئية إن وجدت محفوظة |
| cancelled | 130 | إلغاء؛ النتائج التي وصلت محفوظة |
| error | 1 | قراءة رمز الخطأ: invalid_request أو runtime_error أو io_error |

`limited: true` يعني بلوغ حد المصدر، وليس فشل التشغيل. `eligible` حكم على مطابقة بيانات الأسماء للشروط، وليس إثبات صحة الإصدار أو تصريحا تلقائيا بالتنزيل.
